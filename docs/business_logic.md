# Бізнес-логіка

## 1. Автентифікація та ролі

### Кастомна модель користувача

- **Ідентифікатор** — номер телефону (`USERNAME_FIELD = 'phone'`), не email.
- Модель: `users.CustomUser` (наслідує `AbstractBaseUser + PermissionsMixin`).
- Менеджер: `CustomUserManager` з методами `create_user()` / `create_superuser()`.

### Ролі

| Роль | Значення | Опис |
|------|----------|------|
| `ADMIN` | `admin` | Повний доступ до системи |
| `TEACHER` | `teacher` | Доступ до своїх груп, занять, відвідувань |

- Роль зберігається в полі `role` (TextChoices).
- Helper-властивості: `user.is_admin`, `user.is_teacher`.
- Суперкористувач автоматично отримує роль `ADMIN`.

### Авторизація

- Авторизація за телефоном + паролем через `django.contrib.auth.authenticate()`.
- Усі CRUD-сторінки захищені декоратором `@login_required`.
- Налаштування: `LOGIN_URL = 'login'`, `LOGIN_REDIRECT_URL = 'dashboard'`.

## 2. Гілки (Branch)

- Поля: назва, адреса, місто, статус.
- **Soft delete** — замість видалення: `archive()` → статус `archived`, `restore()` → статус `active`.
- CRUD: список (з фільтром archived), створення, редагування, архівація, відновлення.
- Валідація: назва та місто обов'язкові.

---

## 3. Предмети (Subject)

- Поля: назва, опис, статус.
- **M2M → Branch** — предмет може бути доступний у кількох гілках.
- Архівування аналогічно до Branch.
- CRUD: список (з фільтром по гілці), створення, редагування.

---

## 4. Групи (Group)

- Прив'язка: `FK → Branch`, `FK → Subject`, `FK → Teacher`, `M2M → Student`.
- Вибір викладача обмежений: `limit_choices_to={'role': 'teacher'}`.
- CRUD: список (з фільтром по гілці), створення, редагування.
- Валідація: назва, гілка та предмет обов'язкові; викладач — необов'язковий.

---

## 5. Студенти (Student)

- Особисті дані: ім'я, прізвище, телефон, дата народження.
- Контакти батьків: ПІБ, телефон, email.
- Прив'язка: `FK → Branch` (необов'язковий).
- **Soft delete** — аналогічно до Branch.
- CRUD: список (з фільтрами по гілці та archived), створення, редагування, архівація, відновлення.
- Валідація: ім'я та прізвище обов'язкові.

---

## 6. Абонементи (SubscriptionPlan)

- Визначає: назву, кількість занять, ціну, тривалість (днів).
- Прив'язка: `FK → Branch`.
- Управління через Django Admin.

---

## 7. Заняття (Lesson)

- Прив'язка: `FK → Group`, `FK → Teacher`.
- Поля: дата, час початку/закінчення, тема, статус.
- Статуси: `scheduled` → `completed` / `cancelled`.
- Сортування: за датою та часом початку.

---

## 8. Відвідування (Attendance)

- Прив'язка: `FK → Lesson`, `FK → Student`.
- Статуси: `present`, `absent`, `late`.
- **Constraint**: один запис на студента на заняття (`unique_together`).
- Поле `note` для приміток.

---

## Загальні патерни

| Патерн | Де використовується |
|--------|---------------------|
| Soft delete (archive/restore) | Branch, Student, Subject |
| TextChoices для статусів | Усі моделі зі статусами |
| `auto_now_add` для `created_at` | Усі моделі |
| `select_related` в запитах | Group list, Student list |
| Фільтрація в списках через GET-параметри | Branches, Subjects, Groups, Students |
